## ⚠️ 戦略追記 (2026-04-30, セッション末尾)

### 出版仕様 (確定)
- **判型**: B6 (128×182mm) 350dpi = 1748×2480 px (本文)、塗り足し3mm 込み 1843×2587 px
- **販路**: Amazon KDP Select (= KU 専売) + Amazon Print on Demand (紙) 両出し
- **1巻**: 160-200ページ / 電子 700円 / 紙 800-1000円
- **目標**: 月10作品 × 2巻 × 1000部 = 月1400万円 (年1.68億)
- **ジャンル**: 異世界なろう系特化 (3サブジャンル並行: ダンジョン探索 / 転生貴族・領地経営 / 現代ダンジョン)
- **画風**: 作品ごとに別 (`manga_bw_seinen_dark` / `manga_bw_shoujo_classic` / `manga_bw_seinen_urban`)
- **人手介入範囲**: プロンプト調整 + 最終仕上げのみ (誤字脱字・トーン濃淡・吹き出し位置)。線画修正・コマ手描きは入れない

### Phase A / Phase B 2段階戦略

**Phase A (検証フェーズ、9-12ヶ月)**: 1人運用で3作品×2巻=1200ページ完成 → KDP+KU 出版 → 売上反応で Phase B 移行判定。本plan の17週工程をベースに、9-12ヶ月に延長前提。

**Phase B (量産フェーズ、Phase A 成功時のみ)**: 月10作品スケール検証。Phase A の repair ログから自動化箇所を特定 → アシスタント雇用 or 自動化詰める。同ジャンル特化で読者リスト共有を狙う。

## Context

2026-04-30、Year2のピボット先を**縦読み(webtoon)→横読み白黒(集英社/講談社系)**に変更決定。買い手筆頭は集英社/講談社/KADOKAWA、AI生成日本漫画は前例薄で差別化資産。中核戦略は白黒+トーン+SVG吹き出し合成で「AIらしさ問題」を回避し日本漫画の様式美に乗ること。

最新の小説SOTA研究 (Agents' Room ICLR2025 / StoryWriter CIKM2025 / DOC ACL2023) のナレッジを漫画パイプラインに転用するため、Codexと**5ラウンド議論**して設計を確定。

### 既存メモリで確定済みの方針(`project_manga_models_2026.md` 完全踏襲)

**3段階戦略**:
1. **MVP (今〜2-3週間)**: **gpt-image-2 単一**(2026-04-21リリース、O-series reasoning統合、日本語密レイアウトflawless、16枚参照、edit API有、5月初旬API開放/Foundryは即)。**ChatGPT/Codex経由で先行検証 → 5月API開放後に自動化**。**16枚参照で2300冊蔵書を圧縮活用**(スタイルシート/キャラシート/コマ割りリファレンス)
2. **評価ベンチ (MVP並行)**: gpt-image-2 vs Niji 7 vs Flux 2 vs Qwen-Image 2.0 を**新規1話書き下ろし**で比較。Flux 2 と Qwen-Image はセルフホスト先行(ユーザー指定)
3. **Phase 3 (3-6ヶ月後、差別化期)**: gpt-image-2で「AI量産物」判定が出たら **Flux 2 + 自社 LoRA**(2300冊蔵書からスタイル特化LoRA + character consistency LoRA)

**確定方針(多言語前提のため)**:
- **吹き出しはSVG重ね固定** — Phase1多言語戦略あり、画像内描画は翻訳版で再生成不可。NovelAIのbubble直接描画やgpt-image-2の日本語精度高でも画像内描画は採用しない
- **art_style強制** — `manga_bw_shounen` / `manga_bw_seinen` をプロンプトで `monochrome / screentone / no color shading` 強制(白黒+トーン+SVG吹き出しでAIらしさ問題を回避する戦略の中核)
- **L1.5(ページレイアウト)の必要性は実テストで判断** — gpt-image-2でページ一発生成(F-2)が成立するなら、コマ単位生成+SVG合成(F-1)のL1.5は不要になる可能性

**「MVP 2-3週間」と本plan「17週」の関係**: メモリの「2-3週間」は **gpt-image-2単一固定で動かす検証期間**(Week 0 + 評価ベンチ並行の初動)を指す。本planの17週は **24ページ1話MVP + 2-3話量産検証完了までの工程**全体。メモリ・本planとも矛盾しない(粒度の違い)。

**評価ベンチに含めない4モデルの理由**:
- **Wan 2.7-Image-Pro** (Alibaba クローズド、4K+12言語) — 漫画/白黒特化なし、Qwen-Image系列で代替可
- **NovelAI V4.5** — speech bubble直接描画機能はあるが、SVG重ね方針と矛盾
- **Imagen 4** — multi-panel可だが特化なし、few-shot subject customization非対応でキャラ連続コマに不利
- **SDXL/Pony + manga LoRA** — Phase 3でFlux 2 LoRA を選択したため不要

## アーキテクチャ

5層パイプライン + ModelCapabilityProfile + RenderAdapter による作画限界制約とモデル切替対応。

```
L0   Story Intent      既存流用
L1   Episode Beat Plan 既存流用 (plot-extractor, scene-splitter)
L1.2 Panel Name        既存改修 (storyboard-builder)
L1.4 Page Direction    ★Month 1新規 (page-director/) — PagePlan IR
L2   Render + Bubble   Month 2-3 (RenderAdapter + bubble/vertical/ + spread/ビューア)

* ModelCapabilityProfile (Week 0成果物) — モデル別能力プロファイル
* RenderConstraints      (Month 1) — PagePlan mapper制約
* RenderAdapter          (Month 1抽象化、Month 2実装) — gpt-image-2/Niji/Flux/Qwen切替
```

エージェント粒度4(Name Planner / Page Director / Continuity Checker / Judge-Repair)、LLM呼び出し2.5段化(storyboard-builder → page-mapper → continuity-pass)。

## Week 0: Image Feasibility Gate (5-7日)

**目的**: gpt-image-2(Foundry先行 or ChatGPT/Codex経由)で日本漫画白黒様式がどこまで再現できるかを実測し、`ModelCapabilityProfile` を確定。Month 1以降のPagePlan制約の前提となる。

### 本実験 100枚 (Day 3-5、Pilot合格後のみ)

| 実験 | 内容 | 枚数 | 合格ライン |
|---|---|---:|---|
| **A** 白黒漫画スタイル | 単一キャラ・単一ポーズ・単一表情 | 20 | 12/20「使える」、5/20「商業候補」 |
