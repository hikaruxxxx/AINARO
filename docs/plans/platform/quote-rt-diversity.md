# 引用RTのAI感低減：パターン拡張＋多様性強制

## Context

@sakiyomiAIの引用RT自動生成が定型化し、AI感が強く出ている。直近10件のdraft_textを実測した結果、80%が「すごい、でも」パターン1択で、全件が同一の4ブロック構造（[肯定]→[ただ、ぼくが気になるのは]→[会計士視点]→[〜の設計の方が先]）。語彙も「設計」16回・「論点」8回・「〜の方」11回と偏り、「足す論点」も全件「コンプライアンス／監査」に一元化していた。

memoryの`feedback_x_winning_patterns.md`では9パターン（A面3+B面6）が定義されているが、コード上は3パターンのみ実装、しかも実質1パターンしか動いていない。

目的: パターン多様性を**構造的に強制**して、読者側に「またこれか」と認識される定型を解体する。

## 改善設計

### A. パターン定義の拡張（3 → 10）

引用RT用途に10パターンを採用（長文・連載は単発引用RTに不向きなので除外）。
**P0系**（素直紹介系）3つと**P1-P7**（捻り系）7つの構成。
全引用RTを「会計士視点で捻る」必要はなく、純粋に「これ良かった」だけで終わる引用RTも自然な発信として混ぜる。

各パターンに「冒頭テンプレ」「結びの型」「文字数レンジ」「専用語彙」を設定する。

| ID | 名前 | 文字数 | 冒頭テンプレ | 結びの型 |
|---|---|---|---|---|
| P0a | 素直に紹介型 | 100-160 | 「これは読んでおきたい」「面白かった」 | 一行コメント or 推奨 |
| P0b | ハイライト抽出型 | 120-180 | 「特に効くのはここ」「刺さるのは〜」 | 元ポストの一部を引いて補強 |
| P0c | 実用報告型 | 140-200 | 「試した。◯◯に効いた」「使ってみた」 | 効果を具体に |
| P1 | すごい、でも | 240-260 | 元ポストの肯定1行 | 「〜の方が先」 |
| P2 | 問いで終わる | 180-220 | 観察 or 数字 | 疑問形「〜か」 |
| P3 | バズ記事の先 | 220-260 | 元論点を肯定 | 「次の論点は〜」 |
| P4 | 失敗告白型 | 140-180 | 「ぼくも◯◯で失敗した」 | 学びを断定 |
| P5 | 巻き込み質問型 | 160-220 | 「◯◯の方、これどう処理していますか」 | 直接質問 |
| P6 | 逆張り断定型 | 160-200 | 「みんな〜と言う。違う」 | 断定「〜が本筋」 |
| P7 | 鮮度タイムスタンプ型 | 180-220 | 「さっき／今朝／たった今」 | 観察か即時アクション |

**重要**: P0系（素直に紹介）は全体の30〜40%を占める想定。毎回捻らない。元ポストが純粋に有用な情報源（公式リリース、技術解説、有用なTips）の場合、会計士視点の捻りを無理に足さず、「これは効く」「ここが面白い」だけで終える方が自然。

### B. 多様性の強制機構

**(1) 直近パターン除外**: `quote-post-queue.json` の末尾3件の `pattern_hint` を読み、Grokに「同じpatternを避けろ」と指示。

**(2) angle_category 7カテゴリのローテ**: Grokの出力スキーマに `angle_category` を追加。直近3件で未出のカテゴリを優先するよう指示する。
- **none**（捻らず純粋に紹介。P0系で使う）
- compliance（コンプラ・監査・守秘義務）
- organization（組織・採用・チーム設計）
- career（キャリア・スキル・労働市場）
- business_model（収益構造・価格設計・チャネル）
- market_structure（業界構造・競合・参入障壁）
- tech_structure（システム設計・データ・運用）

これが「セキュリティ一辺倒」を解く最重要レバー。捻らない選択肢（none）も明示的に持つ。

**(3) 文字数はpattern定義に従属**（独立ランダムにはしない）。pattern選択でほぼ決まる。

### C. NGリスト（二層）

**Hard NG（絶対禁止）**: 4ブロック定型を直接潰す
- 「ぼくが気になるのは」
- 「ぼくが見ているのは」
- 「設計の方が先」「論点の方が先」
- 「ただ、ぼくが」（このフレーズで始まる転換段の禁止。P1のみ別の言い回しで許可）

**Soft NG（本文中1回まで）**: 過剰使用を制限
- 「設計」「論点」「〜の方」「ただ、」

**構造NG**: 「[肯定]→[ただ]→[ぼくが]→[〜の方]」の4段定型を構造として明示禁止。

### D. 多候補→1案セルフ選定

claude -p のプロンプト末尾に「内部で3案生成し、口癖反復が最も少なく pattern らしさが立つ1案だけを最終出力」と指示。1リクエストで完結（コスト規模維持）。

### E. キャラ維持・道具分散

**維持**: 一人称「ぼく」、断定/問いの語尾、静かな異端者トーン、名詞中心。

**分散（pattern別に切り替え）**: 接続詞（「ただ、」はP1専用）、結びの型（「〜の方」はP1専用）、一人称頻度（P7短文では省略可）。

## 実装ステップ

### Step 1: `x_research_grok.py`
- `WINNING_PATTERNS` 定数を7パターン定義dict（冒頭/結び/文字数/専用語彙）に書き換え
- `build_prompt()` に `recent_patterns: list[str]` と `recent_categories: list[str]` 引数追加
- 出力スキーマに `angle_category` を追加（6択）
- Grok指示に「直近3件と同じpattern_hint・angle_categoryを避ける」を明記

### Step 2: `task_quote_rt_fetch.py`
- `load_recent_patterns(n=3)` 関数追加: queue末尾n件の `pattern_hint` と `angle_category` を返す
- `search_x_via_grok` 呼び出し時にこの履歴を渡す
- 候補保存時に `angle_category` も一緒に保存

### Step 3: `task_quote_rt_fetch.py:generate_draft_with_claude()`
プロンプトを動的構築型に書き換え:
- pattern_hintに対応する**冒頭テンプレ・結びの型・文字数・専用語彙**だけを動的埋め込み（7パターンを毎回全部見せない）
- `angle_category` を表示し「この角度から書く」と明示
- 過去ヒット例も**選択patternに対応する1例だけ**を埋め込み（3例固定をやめる、これが収束の主因）
- Hard NG / Soft NG / 構造NG を追加
- 「3案内部生成→1案最終出力」を末尾に追加

### Step 4: pattern別例文ライブラリ
`task_quote_rt_fetch.py` 内に dict として保持。
- P0a-P0c: 新規作成。「これ効く。特に〜の部分」「試した。◯◯に刺さる」のような短いコメント形式
- P1-P3: 既存の過去ヒット投稿（ハマりすぎないよう例数を絞る）
- P4-P7: 新規作成（@sakiyomiAI過去投稿に近い文体で2件ずつ）

### Step 5: 検証（2週間ガード）
14日 × 2件 = 28件運用後、以下を週次で確認:
- pattern分布が均等か（各パターン3〜5件）
- angle_category分布が均等か
- 文字数分布が140〜280字に広がっているか
- Hard NG使用ゼロ・Soft NG平均1回以下
- 偏りが残っていればNG閾値・pattern定義を再調整
