# 30. item_analysis — アイテム解析・ステータス画面

scene_id: `item_analysis`
genres: `dungeon-modern` (主) + `isekai-tensei-cheat` (派生)
function: `worldbuilding` + `decoration`

新アイテム / スキル / レベルアップ等の **ゲーム的要素** を視覚 UI で提示する場面。
ナレーション禁則 (L0-2) を回避するため、説明枠は別レイヤーで処理する。

---

## L0 参照

- L0-2 (ナレーション禁則): アイテム説明枠は **「ナレーション枠」ではなく「視覚 UI」**
  として扱う。読者が "ゲーム画面を見ている感覚" で読めるよう設計
- L0-1 (panel = 物語進行単位): アイテム解析 panel も「アイテム情報の伝達 + 主人公の
  リアクション」の 2 機能まで

---

## L1 MUST

### 1. アイテム説明枠は別レイヤー
新規アイテム / スキル登場時は **灰色背景の矩形枠** で「名前 + 効果 + 価格」を
別レイヤー記述する。会話吹き出しとは明確に分ける。

例:
- 「(黒) D メダル 換金額 一枚 50 円」
- 「炎の石 装備の属性を変化させる石 販売所買取 ¥320,000」
- 「スキル玉: 舐めるとスキルを覚える 決して噛んではいけない 偽装されている」

### 2. ステータス画面 panel は章末・章頭で更新
レベル / HP / 攻撃 / スキル / 幸運値などのステータス画面 panel は **章末 or 章頭**
で必ず 1 回は表示する。読者は "ゲームのステータス画面" として瞬時に把握する。

例:
- 「壱野泰良: レベル 1 体力 15/15 攻撃 3 幸運 100 スキル無」

### 3. 主人公のリアクションをセットで
アイテム説明枠 / ステータス画面 panel の **直後** に、必ず主人公の表情・独白の
panel を置く。情報を投げっぱなしにしない。

```
panel A: アイテム説明枠 (灰色矩形・別レイヤー)
panel B: 主人公の表情 + 独白「これは...!」
```

---

## L2 SHOULD

### 1. アイテム単体大コマ
新アイテム初登場時は **アイテム単体の大コマ** を 1 panel 立てる。情報枠と分けて
"物理的な存在感" を絵で示す。

### 2. 価格枠は別レイヤー
換金額 / 販売価格は説明枠とは別の小さい矩形に。「10 万円!?」のような
読者の驚きを誘発する数値は太字 / 大きく。

### 3. 「危険警告」風の注釈
「決して噛んではいけない」のような注意喚起調を含めると、読者は世界の
ゲーム性を実感する。アイテムの不完全さ・偽装情報を匂わせる時に有効。

例 (kindle-test-1 page_0144):
- 「スキル玉: 舐めるとスキルを覚える 決して噛んではいけない 偽装されている」

### 4. 鑑定スキル発動の演出
鑑定スキルを発動する panel は、視線・指の動き + エフェクトで演出。
鑑定後にステータスがオーバーレイ表示される流れ。

---

## L3 MAY

### 1. SNS / 配信での価格反応
アイテム価格が SNS で話題になる SNS panel と組み合わせる
(`30_scenes/social_reaction.md` 参照)。

例: 「炎の石 ¥320,000」→ Twitter「マジか…」「買えん」

### 2. インベントリ画面
複数アイテムをまとめて表示する画面。1 巻に 1-2 回程度、章末でまとめて。

### 3. スキルツリー画面
レベルアップ時のスキル選択 UI。`isekai-tensei-cheat` 系で多用される。
`dungeon-modern` 系では稀。

---

## 典型 panel 構成例

### パターン A: アイテム解析 標準 (4-6 panel/page)
- panel 1 (upper-right, 大コマ): アイテム単体の引き or クローズアップ
- panel 2 (upper-left, 中ゴマ): 鑑定スキル発動の演出 (視線・指)
- panel 3 (middle, 大コマ・横長): アイテム説明枠 (灰色矩形・別レイヤー)
- panel 4 (middle-right): 主人公の表情リアクション
- panel 5 (bottom-left): 主人公の独白 (雲型) or マスコットの軽いツッコミ
- panel 6 (bottom): 引き or 次への展開

### パターン B: ステータス画面更新 (章末)
- panel 1 (大コマ・全画面): ステータス画面 panel
  「壱野泰良: レベル 5 体力 50/50 攻撃 12 幸運 100 スキル: 鑑定 / 詳細鑑定」
- panel 2 (中ゴマ): 主人公の手 (スマホ的なデバイスを見ている)
- panel 3 (中ゴマ): 主人公の独白「ここまで来たか…」
- panel 4 (引き): 場面転換 or 章末ロゴ

### パターン C: アイテム + SNS 反応 (社会的影響)
- panel 1 (大コマ): アイテム単体
- panel 2 (中ゴマ): アイテム説明枠
- panel 3 (上半分): SNS 画面 (Twitter/X 風)「マジで!?」「再生数 10 万!?」
- panel 4 (下半分): 主人公がスマホを見ている引き

---

## 失敗パターン

- **アイテム説明枠をナレーション枠で代用**: 灰色矩形の **別レイヤー** で書かないと
  L0-2 違反扱い。視覚的に区別すること
- **ステータス画面を毎ページに置く**: 情報過多になり退屈。章末・章頭で 1 回ずつが目安
- **アイテム説明枠の後にリアクション無し**: 情報を投げっぱなしにすると読者が
  情報処理できず脱落。必ず主人公の表情 / 独白を直後に
- **アイテムの大コマ省略**: 説明枠だけだと "物理的な存在感" が伝わらない。
  単体大コマ + 説明枠のセットで使う
- **「危険警告」濫用**: 全アイテムに警告を付けると意味が希釈する。1 巻に 2-3 個まで

### 追加実例 (2026-05-06 レベルガチャ Vol.1-3 精読)

- **レベルガチャ Vol.3 (vid3 t45s = spread ~75)**: ステータス画面が **2 ページ全面の見開き**。
  詳細スキルリスト + Lv 表記 + 数値 before/after 矢印「121 (←115)」
  + ガチャ rarity 分類 (R/SR/SSR の色分け +個数) + 「New」マーカー = ガチャ
  ゲーム UI を完全模倣
- **レベルガチャ Vol.1 (spread 8, 18)**: ガチャ pull 時の 2 ページ見開き演出。
  「ガチャ!!」「ジャラララ!」「キラッ」等の効果音オノマトペが panel を支配。
  「1 回ガチャ」「10 回ガチャ」のボタン UI も panel に直接描画
- **レベルガチャ Vol.1 spread 18 (スキルオーブ panel)**: 6 種スキル icon を
  グリッド配置「X / 渦 / 炎 / 水 / 投擲 / 移動」+ 灰色背景 +「《スキルオーブ》を
  使用しますか? はい / いいえ」UI prompt
- **レベルガチャ Vol.1 spread 36 (冒険者カード)**: 冒険者プロフィール UI として
  キャラステータスを長方形カード型 panel で表示 = ステータス画面の派生形 (簡易版)。
  「アマチショウタ 天地翔太 / 年齢 21 / レベル 31 / 攻撃 34 / 範囲 34 / 投擲 34 /
  知力 32 / 魔力 32 / 達 60」
- **レベルガチャ Vol.1 spread 36 (レベル数値変化)**: 「レベル31」 → arrow → 「レベル3」
  の数値変化を矢印付き panel で視覚化 (down-grade の演出)
- **レベルガチャ Vol.1 spread 44**: 戦闘ドロップ後のリボン型 UI
  「ドロップアイテム」+ 「鉄のナイフ×1」「極小魔石×1」 = 灰色矩形ではなく
  リボン状の枠装飾型
- **レベルガチャ全 3 巻**: 主人公装備が **甲冑** (kindle-test-1 は制服のまま戦闘)。
  ダンジョン入る/出るで装備の切り替え panel を入れることで「現代と異世界要素の境界」を可視化

### gacha_ui の UI 階層整理

`bible.subtype = gacha_ui` 系で確認できた UI panel の階層:

| 階層 | UI | 出現頻度 | 用途 |
|---|---|---|---|
| L1 | 2 ページ全面ステータス画面 | 1-2 回/巻 | 大きなステータス更新時 (rarity 入手等) |
| L2 | 冒険者カード型プロフィール | 数回/巻 | 受付・支部訪問・身分証明場面 |
| L2 | スキル icon グリッド + UI prompt | 1-2 回/巻 | 新スキル獲得選択 |
| L3 | リボン型 ドロップ UI | 戦闘毎 | 戦利品の即時表示 |
| L3 | 数値矢印 (Before → After) | 数回/巻 | レベル変動の可視化 |
| L3 | マップ UI (タブレット風) | 階層変動毎 | 新空間突入時の establishing 補助 |

### ジャンル一般化メモ

`dungeon-modern` には **2 サブタイプ** が存在:

- **(A) 簡素 UI 型 = kindle-test-1**: ステータスは 1 panel・要点のみ。社会的反応は SNS で外出し
- **(B) ガチャゲーム UI 型 = レベルガチャ**: ステータスは 2 ページ全面・スキル一覧詳細。社会的反応は内部 UI (rarity / level up) で完結

storyboard-builder への注入時、bible 設定で `subtype: gacha_ui` のフラグを持つ
作品では (B) のパターンを採用する想定。

- (kindle-vol-4 待ち: battle_dungeon 系・isekai_tensei_cheat 系での共通点 / 差分)
- (kindle-vol-3 候補待ち: 領地経営系では **領地ステータス画面** (人口・収穫高) が
  代替する予想)
